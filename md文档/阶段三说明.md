# 阶段三：同类题与在线复习

## 1. 当前交付范围

已经实现以下闭环，默认可以在微信开发者工具的本地演示模式中运行：

```text
错题详情 → 出题配置 → 候选题 → 编辑/确认 → 在线练习 → 答案解析 → 历史记录
```

本地模式使用模板出题并标记“演示出题”。云端已实现 `cloudfunctions/api/ai-adapter.js` 真实服务适配器，通过环境变量配置 Chat Completions 兼容供应商；未配置时显示“AI 待配置”，明确配置演示模式时才运行模板。配置、兼容参数和部署步骤见 [真实AI接入说明](真实AI接入说明.md)。当前尚未完成实际供应商联通及真实云部署验收。

## 2. 页面与交互

| 页面 | 已实现行为 |
| --- | --- |
| 错题详情 | “生成同类题”入口 |
| 同类题 | 数量 1～3，基础/一般/提高难度，生成、再生成、编辑、删除、逐题确认 |
| 复习 | 按学生筛选，练习/记录/待确认三个视图 |
| 在线练习 | 隐藏答案与解析，填写答案，提交后显示结果 |
| 练习结果 | 显示提交时题目、答案、解析；开放题可由家长标记对/错/暂不判定 |

再次生成会新增一批候选题。每批最多三道，已有确认题和历史记录继续保留。

编辑已确认题后，题目回到 `draft`，需要再次确认。原错题已删除时，候选题仍可查看、编辑和删除，但不能再生成或确认；已有练习记录可以继续查看。

## 3. 演示出题范围

| 类别 | 示例输入 | 判题方式 |
| --- | --- | --- |
| 整数单步计算 | `23 × 14 =`、`12 + 3 =`、`24 - 7 =`、`48 ÷ 6 =` | 唯一答案，系统判定 |
| 一步应用题 | 题型选择“应用题”，如“每盒有5支铅笔，3盒一共有多少支？” | 家长判定，保留单位和合理表达 |
| 拼音和字词 | “给山写拼音并组词” | 家长判定 |
| 近义词、反义词 | “请写出美丽的近义词” | 家长判定，避免把其他合理答案判错 |

演示模板根据题目形式或知识点选择类别，不能保证精确匹配教材、年级、错误原因和实际教学难度。数学计算模板会调整数字大小；语文和应用题模板的难度主要作为配置记录保存。真实模型接入后仍需人工确认生成结果。

范围外题目会提示暂不支持，并保存失败任务；不会复制原题并声称生成成功。计算模板只接受完整的整数单步算式，不将小数、复合算式或文字题中的局部数字误识别为完整算式。

## 4. 数据和状态

新增 `generated_questions`、`practice_records`、`tasks` 三个集合，本地模式提供对应缓存。

| 数据 | 关键内容 |
| --- | --- |
| 生成题 | 当前用户、学生、学科、年级、原错题 ID、来源版本、任务 ID、出题方式、题目、答案、解析、状态、版本 |
| 练习记录 | 当前用户、学生、生成题 ID、提交编号、答案、判题结果、提交时间、题目完整快照 |
| 生成任务 | 当前用户、学生、原错题 ID、来源版本、出题方式、状态、成功题目 ID 或失败信息 |

生成题状态为 `draft → confirmed`，编辑后回到 `draft`；删除设为 `deleted`。复习记录结果为 `correct / wrong / ungraded`。

原错题内容变化会更新来源版本，旧候选题不能确认。仅修改掌握状态不会要求重新出题。确认后才可进入练习；练习开始和列表接口隐藏答案与解析，提交后通过快照展示。

提交编号用于防止网络重试形成重复记录。正在作答的题目被修改时，版本校验阻止按新答案误判旧作答。修改或删除生成题不改变已保存的快照，开放题也可以根据历史快照重新标记结果。

删除学生前同时检查错题、未删除生成题和历史练习记录，避免产生无归属的复习历史。

## 5. 接口

| 接口 | 作用 |
| --- | --- |
| `generation.create` | 服务端读取原错题，调用适配器，校验 JSON、数量、字段、难度、来源版本，保存候选题和任务 |
| `generation.config` | 返回出题模式和配置就绪状态，不返回服务密钥 |
| `task.get`（`type=generation`） | 按任务 ID 或请求编号恢复出题任务；超时任务标记失败 |
| `generation.list` | 获取当前用户的候选题，支持学生、来源和状态筛选 |
| `generation.update` | 修改候选题，返回待确认状态 |
| `generation.confirm` | 校验来源版本并确认题目 |
| `generation.delete` | 软删除生成题 |
| `practice.list` | 获取已确认的练习题，隐藏答案和解析 |
| `practice.start` | 检查题目归属和确认状态，返回作答题目及版本 |
| `practice.submit` | 验证答案和提交编号，判定结果并保存快照；同编号重试返回原记录 |
| `practice.records` | 查询当前用户的复习历史，支持按学生筛选 |
| `practice.detail` | 查询一条历史记录及快照 |
| `practice.grade` | 家长更新开放题判定；客观题保持系统判定 |

云函数中的生成批次写入、候选题编辑确认、练习提交使用事务。失败任务会留档；写入中途失败不会保留半批候选题。

共用规则以 `miniprogram/services/practice-domain.js` 为源文件，通过 `npm.cmd run build` 同步至云函数。部署前运行一次；测试和检查会自动同步。云函数只依赖自身目录内的规则文件，不依赖项目外部相对路径。

## 6. 验证与手动验收

自动化覆盖本地模式和模拟云函数的生成、编辑确认、作答、家长判定、历史快照、用户隔离、来源变化、数量难度边界、JSON 错误和写入失败回滚。同时覆盖页面事件从生成到历史查看的调用流程。

建议在微信开发者工具中完成以下手动验收：

1. 添加三年级学生，录入数学题 `23 × 14 =`。
2. 从详情生成三道题，检查每道题均有题目、答案和解析。
3. 在复习“待确认”中查看候选题，确认其尚未出现在“练习”中。
4. 将一道题修改为 `30 + 2 =`，答案 `32`，补充解析，保存并确认。
5. 进入练习，确认作答前不显示答案；提交 `32`，检查结果为答对。
6. 再次练习提交 `3.2`，检查结果为答错，不能因移除小数点误判为 `32`。
7. 进入记录查看快照；将生成题修改为 `40 + 2 =`，检查新题需要重新确认，旧记录仍为 `30 + 2 =`。
8. 录入近义词或拼音题，生成确认后作答，检查先保存待判定，再由家长标记结果。
9. 添加第二个学生，切换复习筛选，检查题目和记录按学生分开。
10. 使用真实云环境时，创建三个新增集合，部署云函数，再重复上述验收。

当前已进行自动化和模板编译验证，尚未进行真机视觉验收或真实云数据库部署验收。真实 AI 调用适配器已实现，需配置供应商后完成联通和质量验收；OCR 和 PDF 的实现范围见阶段四、五文档。
